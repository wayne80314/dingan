# 個人資料蒐集、處理及利用告知（範本）

> 依個人資料保護法第 8 條告知義務範本，供 M0 正式產品使用。**本文件描述的是完整產品（M0+）的個資告知內容，其中部分段落（尤其 AI 每日摘要相關的境外處理）在 F0 階段尚未實際運作**——F0 階段只有 `spike/` 工具包本身（webhook 事件捕獲、群組成員 profile 探測、測試推播），完全不呼叫任何 AI 摘要 API。若在 F0 試點期間需要向真實業主/設計公司說明個資處理情形，**必須先讀完本文件每一段的「F0 階段」註記**，不能整份直接照發，否則會告知使用者「你的討論內容會被送到 Anthropic 做摘要」這種目前不存在的處理行為。

## 二、蒐集之目的

1. 提供 LINE 群組內決策卡建立、推播、確認之服務
2. 產出決策稽核紀錄與匯出文件（供請款附件/糾紛自保使用）
3. 帳務與訂閱管理
4. **輔助產出每日討論摘要（AI digest）**——**F0 階段：此功能尚未啟用，本告知範本先預留條文供 M0 使用。F0 spike 完全沒有呼叫任何 AI／LLM API。**
5. 服務優化與異常排除（含 raw webhook payload 的除錯用途）

## 三、個人資料之類別

- LINE `userId`、當時顯示名稱（displayName）
- 群組內訊息內容（文字、圖片、影片、檔案）
- 決策卡確認行為（誰、何時、確認了什麼）
- 服務使用紀錄（登入時間、操作紀錄）

## 四、個人資料利用之期間、地區、對象及方式

**期間**：見本文件「七、資料保存期間」。

**地區**：伺服器位於 Cloudflare 全球節點（依產品部署地區調整）；境外傳輸對象見下方「對象」欄位逐項標註。

**對象**：
- LINE（LINE Corporation / LINE 台灣）——訊息收發必經之平台，非我方可控制的第三方處理者。
- Cloudflare（D1／R2 等基礎設施）——資料庫與檔案儲存供應商。
- **Anthropic PBC（Claude API）——用於 AI 每日摘要之自動化處理。⚠️ F0 階段：此對象尚未實際接收任何資料，因為 AI 摘要功能尚未啟用（見「二、蒐集之目的」第 4 點）。此欄位描述的是 M0 正式功能上線後才會發生的境外傳輸，F0 試點期間不適用，不應以此欄位向 F0 試點對象告知「資料已經/正在送往 Anthropic」。** 待 M0 該功能實際上線時，需揭露：Anthropic API 預設保留輸入輸出內容至多約 30 天（依 Anthropic 當時公開政策為準，上線前需重新查證最新政策）。

**方式**：自動化系統處理（webhook 接收、資料庫寫入、API 呼叫），非人工檢閱（除非使用者主動申請客服協助排除異常）。

## 五、當事人之權利

依個人資料保護法第 3 條，當事人得就其個人資料行使查詢、請求閱覽、請求製給複製本、請求補充或更正、請求停止蒐集/處理/利用、請求刪除等權利。行使方式：（正式產品上線時填入聯絡窗口與流程）。

若拒絕提供必要個資（如 LINE userId），將無法使用決策卡確認功能（因為系統無法辨識是誰確認的）。

## 六、加入群組後的同意流程

1. 機器人被加入群組後，狀態標記為 `awaiting_consent`（等待同意）。
2. 機器人於群組內發送**簡版告知 Flex 卡片**＋完整告知文（本文件）連結，說明蒐集目的與範圍。
3. 記錄群組整體「已接受告知」狀態（因群組內多人共用同一對話環境，採群組層級的告知確認，而非要求每個成員個別簽署，兼顾LINE 群組互動的實際使用情境）。
4. **新成員加入既有群組時**，機器人重新對該新成員發送簡版告知（不假設新成員已經看過先前的告知）。

## 七、資料保存期間

- **原始聊天內容**：短期保存 **90 至 180 天**（實際天數依方案調整，正式上線前公告），超過期限後原始訊息內容予以刪除或去識別化，僅保留決策卡本身的稽核紀錄摘要。
- **被引用為決策卡佐證的附件**（圖面、報價單等）：只要對應的決策卡存在，就**長期保留**（不受 90/180 天短期保存規則限制）——因為這些附件是稽核紀錄的一部分，刪除會破壞決策卡的可驗證性。
- **決策卡本身與其稽核紀錄**：伴隨對應 project 的生命週期保留，即使原始聊天內容已過期刪除。

## 八、訊息編輯與收回的處理

- **`unsend`（收回）**：對應的原始訊息內容比照使用者刪除意願處理——如果該訊息尚未被引用為任何決策卡的佐證，則從系統中一併清除（purge）；若已被引用，因為決策卡的完整性/稽核目的優先，保留該引用副本，但會在系統中標記「原訊息已被發送者收回」。
- **`messageEdited`（編輯）**：不覆寫舊內容，改為**版本化保存**（保留編輯前後的每個版本），避免決策卡佐證的訊息內容被事後竄改而查無記錄。

## 九、資安維護措施（概要）

Webhook 簽章驗證（防止偽造請求）、傳輸加密（HTTPS）、資料庫存取權限控管、金鑰與密鑰不落地於程式碼版控（見 `spike/.gitignore`／`spike/.dev.vars.example` 的作法，M0 沿用相同原則並加強）。
